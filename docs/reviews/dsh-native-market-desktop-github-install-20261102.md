# DSH Desktop 全目录安装入口复核

## 目标

让 Desktop 插件商城承担发现、搜索、审核建议、推荐和必装榜展示；用户从完整插件目录选择项目后，可以明确确认 GitHub 来源并交给 DSH Desktop 官方插件管理器。商城目录是否收录、候选审核状态和 `inspect()` 预检不能代替 DSH 的最终安装判定。

## 本次修正

- 全量目录沿用官网目录的数据源和合并方式：公开发现索引 + Catalog + 候选记录，按来源 ID、包名和仓库去重；不把 Catalog 记录数当作全量插件数。2026-11-02 15:34 UTC 回读官网发布数据，合并后为 24,838 条，其中 945 条有 Catalog 收录记录、23,893 条未收录；来源包含 24,171 条公开发现、875 条 Catalog 记录和 806 条候选记录。数字会随官网快照变化。
- 完整目录搜索、分类筛选、收录筛选和审核筛选覆盖全部合并记录。目录加载失败时显式显示不完整状态；榜单摘要校验失败只关闭榜单，不影响完整目录。
- 推荐榜与必装榜读取官网发布快照并核验配套页面声明的 SHA-256，按 `marketplace/rankings/model.js` 的规则排序与分页；当前官网快照有 1,566 条榜单记录，推荐榜 160 条、必装榜 30 条。未收录原因在榜单卡片内展示，榜单位置不改变 Catalog 审核状态。
- 全量目录中的公开 `dsh-plugin`、Catalog 记录和 Store 候选记录，只要仓库地址是规范 GitHub HTTPS 地址且不属于受保护对象，就显示 GitHub 默认分支安装入口。候选未通过、Catalog 未上架和未收录状态仍原样展示为 Store 建议。
- 每次默认分支安装都要求输入带仓库所有者、仓库名和 `DEFAULT` 的确认语；弹窗明确说明该来源没有固定 Catalog Commit。随后只调用 DSH 官方 `pluginManager.installBundle()`。
- DSH `inspect()` 是提示。即使预检拒绝或不可用，已确认请求仍交给官方安装器；成功、失败和未知分别以 DSH 响应及一次 Desktop 安装清单核对为准，不自动重试。
- 商城自身、`@deepseek-ai/*`、DSH 官方仓库、受保护入口 ID、格式错误来源和非 DSH 生态条目不走该入口。已由 Desktop 安装的仓库不会显示重复安装按钮。
- 全量目录继续使用官网合并结果进行搜索、分类、收录/审核筛选和分页；目录列表与搜索控件保持在 Desktop 面板滚动流中。

## 验收证据

使用 disposable Desktop fixtures 覆盖公开发现项、Catalog 未上架项及候选未通过项。重点验证候选状态仍可见、用户未确认时不会调用安装 API、确认后 `inspect()` 拒绝仍不拦截 `installBundle()`，以及 DSH 成功回执与安装清单用于显示实际结果。额外用 805 条发现 fixture 验证超过旧 700 条范围后的记录仍可搜索；推荐榜与必装榜逐页对照官网 `rankingEntries()`，并检查摘要不匹配时完整目录仍可用。

本地验证：`test/desktop-compat.test.mjs` 45/45 通过；`npm run check` 592/592 通过，注册表校验报告 discovery index 24,171 条、10,381,927 字节、gzip 2,541,286 字节。计划校验需在本记录及源码哈希更新后重跑。它们不代表用户安装的真实 Desktop 已完成鼠标滚轮/键盘/UI 验收；真实应用与 Profile 验收仍单独记录。

Catalog 仍固定在 `0.9.29`，直到源码 PR 合并后按新的 Catalog policy plan 单独发布。该源码 PR 不修改真实 DSH Profile，也不执行第三方代码。
