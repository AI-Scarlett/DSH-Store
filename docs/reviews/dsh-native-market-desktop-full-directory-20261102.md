# DSH Desktop 插件商城完整目录复核

## 用户可见问题

成功安装后，DSH Desktop 的插件商城仍显示约 779 条记录。搜索、筛选和翻页只能覆盖当前渲染的数据；在受限的 Desktop 面板中，列表也没有自己的稳定滚动区域。

## 根因

- Desktop 只从 Catalog 加载 `approved` 与 `blocked` 记录。截图中的 779 正好是 33 条已审核记录加 746 条拦截记录；另外 96 条 `unlisted` Catalog 记录也被隐藏。
- Desktop 没有读取官网使用的公开发现索引与候选数据。官网目录通过身份匹配合并公开发现、Catalog-only 和候选记录，所以能展示完整列表。
- 原面板根容器没有高度边界和纵向溢出处理。宿主面板限制可用高度时，卡片会被裁切，滚轮行为也不稳定。

搜索控件原本存在，但它只能查找 Catalog 安装记录；找不到公开发现列表中的插件时，看起来就像搜索失效。

## 对照官网

2026-11-02 在 `https://dsh.store/plugins/` 实际读取到：

- 全部已知记录：20,025
- Catalog 匹配记录：962
- 未收录记录：19,063
- 分类：46
- 官网公开发现索引：19,345 条

使用仓库现有 `marketplace/lib/plugin-directory.js` 的目录合并规则对同一份仓库快照计算，结果也是 20,025 / 962 / 19,063 / 46。Catalog 本身为 875 条（33 approved、746 blocked、96 unlisted），候选库为 806 条；未收录和候选状态不会因此获得安装动作。

## 修复

- Desktop 有界读取并校验 `catalog-index.json`、`discovery-index.json` 和候选记录；Catalog 主索引按 Catalog 元数据中的 SHA-256 与字节数验证。
- 将所有已知记录作为独立浏览目录，同时保留 Catalog 安装数据边界。Catalog 收录状态、审核状态、DSH 已安装状态分别显示。
- 搜索、分类、收录状态、审核状态、排序和分页覆盖完整合并目录；列表在独立纵向滚动区内，搜索和筛选保持在列表之外。
- 目录数据失败时明确提示并显示 Catalog 回退记录，不将回退结果称作完整目录。
- 任何安装/更新结果继续以 DSH Desktop 官方插件管理器返回与安装清单核对为准。
