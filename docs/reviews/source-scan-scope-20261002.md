## 修复

1. 手动预检与自动策略共用固定提交的分发范围解析器。支持正向文件/目录、简单 `*` 和 `**`；纳入隐式 main/bin、manifest、README/许可。exports、类型声明、Bundle 与静态相对引用必须存在于分发范围。此结果是保守超集，不冒充完整 npm pack 实现。
2. 不再因为仓库中未分发的 Python/部署脚本/大型数据而拒绝整包。完整 Git 树获取仍保留 8 MiB 限额；1200 个条目上限作用于选定包，源码 240 个/单文件 256 KiB/合计 2 MiB 限额不变。选中范围内的 docs/tests/dist、压缩 JS 不再被目录名排除。
3. 截断、非法路径、不支持的 files 表达式、嵌套忽略规则、符号链接、子模块、未知/原生制品及动态加载继续阻断自动准入。不完整扫描的未观测权限是 null（unknown），不是 false。
4. `tool.call.toolview` 的活跃引用是注册键归属复核信号，不等于修改官方组件；明确直接覆盖已知官方键与 Loader/Fiber 变更仍为 protectedDsh。动态/别名/模板形式不由静态字符串猜测安全；注释和正则不作为已执行操作。纯文本同名引用可能仍需复核，不作恶意结论。
5. 提交 CLI 对不完整扫描返回 `SUBMISSION_SCAN_INCOMPLETE`，不再将源码读取成功等同完整预检成功。发布的 tests 目录代码也不再降级为仅信息。源码更新检查不把删除行继续当成候选行为。
