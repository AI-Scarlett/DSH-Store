# DSH Desktop 插件目录搜索修复复核

## 复现

在真实 DSH Desktop 当前运行的 DSH Store 0.9.31 中搜索 `im`，结果显示 4,099 条。首屏顺序受目录默认分类/Stars 排序控制；隐藏的审核理由、运行时提示等内部元数据也参与子串匹配，短词因此产生大量噪声，标题命中未排在前面。

## 修复

完整目录现在只搜索用户可发现的插件信息：插件标识、名称、别名、包名、GitHub 仓库、Catalog 搜索词、候选主题、分类和用途描述。审核状态、审核理由、推荐证据链接、榜单解释等内部状态不参加匹配。两字及更短的查询跳过长用途描述；多词查询要求每个词都命中。搜索结果先按名称/包名、仓库、关键词、描述的相关度排序，同分时保留当前目录或榜单原始顺序。

没有改变 DSH Desktop 安装入口、Catalog 审核边界、DSH Profile 或官方插件管理器的最终判断权。

## 验证

- 先添加的回归测试在旧实现上失败：`im` 仍返回描述误命中。
- 修改后，完整目录搜索测试通过；短查询只返回身份相关条目，较长的 `image` 搜索把名称命中排在描述命中之前，`installation` 不会命中审核理由。
- `npm run check` 通过：Registry `875` 条记录通过校验，全部 `593` 项测试通过。
- 桌面端实测复现来自已安装的 `0.9.31`。`0.9.32` 尚未合并和固定到 Catalog，因此真实 Desktop 上的修复结果待 Catalog 发布并更新后验收。
