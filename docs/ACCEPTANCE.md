# 验收方案

## 本地模块门（当前可执行）

```bash
npm run check
```

必须通过：

- 源码语法检查；
- Profile 名称路径穿越拒绝；
- Bundle/依赖归并与来源识别；
- 同源 API 请求通过、跨源请求拒绝；
- Bundle 只插入自身，不禁用官方清单；
- Host 源码不存在文件写入、子进程或 Loader/Fiber 变更原语。

## M1 一次性 Profile 验收

以下步骤尚未执行，执行时不得使用真实 `web` Profile：

1. 创建专用测试 `DSH_HOME` 或一次性 Profile；
2. 记录安装前目录清单和关键文件 SHA-256；
3. 通过官方 `dsh plugin --profile <test> add .` 安装本地项目；
4. 启动 DSH 并确认只有本插件自己的 Bundle/Host/Client 条目新增；
5. 打开“设置 → 插件 → 安全管理”，核对数据与磁盘 manifest；
6. 连续刷新、切换主题、重启 DSH；
7. 比较“安装完成基线”和“运行测试完成”之间的关键文件哈希；
8. 验证 headless、manifest 损坏、缺失依赖和坏链接时 DSH 的行为；
9. 卸载插件并确认测试 Profile 恢复，不留下自有缓存。

## 不可替代的证据

- `npm test` 不证明 DSH 能加载插件；
- HTTP 200 不证明设置页可见；
- 页面可见不证明扫描零写入；
- 安装命令成功不证明重启后仍健康；
- 源码审查不证明真实 Profile 可恢复。

只有对应的命令、文件哈希、进程/端口状态和浏览器可见结果都具备，才能标记该门完成。
