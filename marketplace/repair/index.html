OFFICIAL LEGACY RECOVERY / 官方历史版本修复

旧商城更新失败时，
不要放开第三方构建权限。

本入口只处理 ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED。修复器固定到 Catalog 审核过的完整 Commit，先展示计划并备份，再通过官方 DSH CLI 禁止全部生命周期脚本更新；失败时恢复 Profile。

This recovery path is only for historical DSH STORE installations blocked by pnpm's Git prepare policy. It never enables third-party lifecycle scripts or edits DeepSeek Harness itself.

01 / DISCOVER

用户如何知道

旧版商城继续读取轻量兼容 Catalog。置顶商城卡片会直接显示错误码和本页面地址；官网、GitHub README 与自动更新状态使用同一固定入口。

02 / PLAN

先预览再确认

修复器读取商城版本、固定来源、Profile 前置哈希和 Guardian 状态，只显示包名、版本、脚本名与修改范围，不回传 Profile 内容或环境变量。

03 / APPLY

不执行生命周期脚本

只有输入终端里生成的完整确认语后，才会备份并调用官方 dsh plugin。更新参数固定包含 --ignore-scripts。

04 / VERIFY

验收或回滚

先运行配置合成检查。Guardian 可用时再请求重启并等待新的 Boot ID 稳定；命令、配置或冷启动失败都会保留事务记录并进入回滚。

安全边界

  • 不会修改 DSH 源码或任何 @deepseek-ai/* 官方包。
  • 不会让用户手改 package.json、锁文件或逐个迁移插件。
  • 不会执行 preinstall、install、postinstall 或 prepare。
  • 非交互终端、浮动 Commit、来源不一致、Profile 并发变化或缺少官方 CLI 时均拒绝执行。
  • 没有 Guardian 时只完成包与配置检查，并明确标记“等待用户安全重启”，不会冒充运行验收成功。
