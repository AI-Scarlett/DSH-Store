DSH STORE 用于发现 DeepSeek Harness（DSH）插件、查看公开目录中的来源、版本、权限与兼容性信息，并了解受约束的接入路径。它是第三方商城，不替代 DSH 本体，也不能从网页判断本地 Profile、依赖或运行时一定正常。

USE THE RIGHT SURFACESTORE ≠ RUNTIME

商城 · Catalog · CLI · Profile · 依赖

每层都有不同的可核验入口与处理责任。
01 / WHAT DSH STORE CAN SHOW

从发现开始，不替代本地诊断。

在 插件目录 中可以发现公开展示的插件，并进入详情查看名称、用途、版本、固定来源、权限说明和兼容性信息。目录只是发现与核对入口：条目是否可见、可安装或仅展示，必须以公开 Catalog 与页面显示为准。

版本、固定 Commit、来源与权限的含义，以及“可安装”不等于完整安全审计的边界，见 收录标准。没有证据支持的安全、兼容性或运行结论会保持 unknown，不应补成承诺。

02 / ISSUE LAYERS

访问、可见、安装与运行，
不是同一类问题。

先定位发生在哪一层，再打开相应的公开证据或本地工具。下面是首次排查方向，不会直接修改 DSH、Profile 或插件。

01 / STORE

商城页面

首页、目录或本指南打不开时，先确认目标网页与网络访问。网页可访问不等于本地 DSH 已启动或插件已安装。

02 / CATALOG

目录与可见度

插件不显示时，检查目录筛选、条目状态与公开 Catalog。候选、blocked、unlisted 与可安装条目不是同一状态。

03 / CLI

本地 DSH CLI

安装命令、CLI 版本和终端输出发生在本机 DSH 环境。请在目标设备确认实际 CLI 与命令帮助，而不是只看商城页面。

04 / PROFILE

当前 Profile

浏览网站默认只读。真实安装、启停或 Profile 变更应由用户在 DSH 中确认，并保留计划、备份、健康检查与回滚路径。

05 / DEPENDENCY

插件依赖

插件自身的依赖、生命周期脚本和运行文件属于插件发布物与本地环境问题。目录收录不能替代其真实安装或运行验收。

06 / RUNTIME

运行时异常

插件安装后不可用、功能异常或 DSH 未启动，应回到本地 DSH、目标 Profile、插件文档与运行日志核对；不要把它们归因为商城故障。

03 / PUBLIC EVIDENCE

每一个判断，都回到可复核入口。

商城页面负责展示；公开 Catalog 负责目录事实；固定来源和边界由收录标准解释；本地 CLI、Profile、依赖和运行时则必须在实际设备上单独核验。它们可以关联，但不能互相替代。

插件发现与详情 ↗查看公开目录、插件用途、版本、来源、权限与兼容性信息。 收录标准与证据边界 ↗了解固定 Commit、来源、权限和“收录不等于安全审计”的含义。 公开 Catalog ↗核对目录条目与状态的机器可读权威来源。 常见问题 ↗确认网页、安装、权限、目录、开发和支持的基础边界。 源码与文档 ↗查看公开项目、发布记录和使用说明；不要把页面状态当作本地运行状态。 反馈与问题入口 ↗提交可复现的商城或目录问题；本地运行问题请附上经过脱敏的环境与步骤。
04 / QUICK CHECKS

常见混淆，先在这里拆开。

“插件不显示”是否等于插件不存在？＋

不等于。先检查目录筛选和公开 Catalog 中的条目状态。候选库、blocked、unlisted 或尚未收录的来源，不会被包装成可安装插件。

“商城能打开”是否等于 DSH CLI 或 Profile 正常？＋

不等于。商城页面与本地 DSH CLI、当前 Profile、依赖和运行时是不同层面。网页只证明该网页可访问；本地状态必须在目标设备单独核验。

“可安装”是否等于插件已经通过完整安全审计或运行验收？＋

不等于。它表示条目满足当前目录的来源、结构和策略检查。完整安全审计、真实安装、冷启动、功能效果和故障恢复需要分别提供证据。

遇到安装失败时，第一步该做什么？＋

先保留失败时的命令、目标设备、DSH CLI 版本、当前 Profile 和经过脱敏的错误信息；然后按本页的层级判断是商城、Catalog、CLI、Profile、依赖还是运行时问题。不要连续重试或把不确定的操作写入 Profile。

先看清问题层级、来源与边界，再决定下一步。
