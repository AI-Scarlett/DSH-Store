01 / THE WHY

我们不是先想做一个商城，而是先遇到了一个判断问题。

当 Agent 开始拥有越来越多插件，真正困难的不只是找到功能，而是知道它来自哪里、能做什么、会触碰什么，以及出了问题能否退回。

01起点 / DSH 让一切成为插件

能力增长很快，判断却没有跟上。

插件开始散落在 GitHub、话题页和各种清单里。一个 Star 不能告诉你它需要哪些权限、兼容哪个版本，也不能保证下一次更新仍然是同一份代码。

02第一件事 / DSH STORE 插件

先把“能不能放心接入”说清楚。

DSH STORE 插件与商城因此成为一个可信的第三方入口：精选与完整目录分开，来源固定到 Commit，权限和兼容性摆在明面上，浏览默认只读，未知信息不被包装成结论。

03第二个问题 / 开发从哪里开始

但一个生态不能只等别人提交插件。

如果每位开发者都要从猜 manifest、Bundle、权限和验收方式开始，插件会越来越多，标准却不会自然出现。

04第二件事 / build-dsh-plugin

让“我有一个问题”变成“我有一个可验证的插件”。

build-dsh-plugin 是开源 Agent Skill：它把问题、期望结果和成功标准转换成标准工程、风险边界、测试与交付证据；开发者可以把它交给任意编程 Agent，也可以在兼容时通过 DSH STORE 安装到 DSH。

从真实问题出发→用 Skill 构建→在 DSH STORE 检查与接入
02 / PRODUCTS

两个产品，一条清楚的生态路径。

DSH STORE 解决“发现与接入”，build-dsh-plugin 解决“从问题到插件”；它们共同把使用者与开发者连接起来。

01DSH STORE

让用户敢于发现和接入

面向 DSH 用户和开发者的插件商城，提供精选入口、完整目录、固定来源、权限说明和可恢复的接入边界。

02BUILD-DSH-PLUGIN

让开发者有路可走

面向任何编程 Agent 的开源 Skill，把 Brief 变成标准 DSH 工程、审计、测试与证据；兼容时也可由 DSH STORE 安装到 DSH。

03FEEDBACK LOOP

从构建到上架，形成反馈回路

开发者用 Skill 构建，提交到商城接受固定来源与策略检查，用户再从 DSH STORE 发现并接入，真实反馈继续推动下一版。

03 / BRAND

DSH.STORE 是一个关于“可信扩展”的品牌。

我们相信，AI Agent 的能力会越来越多，但用户不应该因此失去判断和控制。好的商城既要有科技感，也要让安全、可信和方便真实发生。
